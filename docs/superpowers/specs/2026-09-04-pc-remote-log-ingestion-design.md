# PC 远程日志获取与分析重构设计

## 目标

重构 PC 日志采集链路，使终端只负责把每日 JSON 日志写入一个汇总共享目录，`net` 项目的独立 Worker 主动通过 SMB 或 FTP/FTPS 获取、导入、分析并归档日志。废除终端直接调用 Django API 的方式，同时复用和升级现有任务队列、日志分析、异常记录、告警和导出能力。

目标链路：

```text
PC 定时运行采集脚本
  -> 汇总共享目录
  -> Worker 创建并执行 PC 日志获取任务
  -> 本地临时文件与完整性校验
  -> 日志入库及 PC 静态资产更新
  -> PC 日志分析子任务
  -> 多线程规则分析
  -> 异常记录、告警与远端归档
```

## 范围

本次包含：

- 一个全局 PC 日志来源，连接方式可选择 SMB 或 FTP/FTPS。
- Windows 和 Linux 服务器上的 Worker 均可主动访问日志来源。
- Windows 与 macOS 采集脚本改为文件共享投递，不再调用 HTTP API。
- 每台 PC 每个自然日最多生成一份正式日志和一次默认分析。
- 手动获取、定时获取、连接测试、文件预览、手动结束及失败恢复。
- 合并旧 Windows 采集脚本和旧 Python 分析规则中仍有价值的能力。
- PC、人员、域账号、域计算机、OU 和场地数据的数据库关联。

本次不包含：

- 终端到共享目录之外的新消息队列或 Agent 常驻服务。
- Excel 作为分析流水线中间格式。
- 多个同时启用的 PC 日志来源。
- 将旧脚本中的硬编码地址、账号、密码或组织结构直接复制进项目。

## 架构选择

采用“远程连接器下载到本地暂存，再复用现有导入和分析流程”。

连接器只负责远端文件操作，导入器只负责验证和保存证据，分析器只负责根据已入库 JSON 生成结果。SMB 与 FTP/FTPS 实现同一个接口，使上层任务不依赖具体协议。

不直接在远程流上分析，因为网络中断、文件仍在写入及远端移动失败会污染分析事务。也不保留独立同步脚本，因为它会让连接配置、执行状态、错误提示和任务取消分散到 Django 之外。

## 配置模型

新增单例 `PCLogSourceConfig`，只允许存在一条有效配置。它包含：

### 通用字段

- `source_type`：`smb` 或 `ftp`。
- `terminal_windows_path`：写入 Windows 下载脚本的 UNC 汇总目录。
- `terminal_macos_path`：写入 macOS 下载脚本的预挂载目录。
- `remote_incoming_directory`：待处理目录。
- `remote_processed_directory`：已处理目录，默认 `processed`。
- `remote_failed_directory`：失败目录，默认 `failed`。
- `local_staging_directory`：Worker 本地临时目录。
- `recursive`：是否递归发现 JSON。
- 最近一次连接测试结果、时间和脱敏错误摘要。

### SMB 字段

- 服务器地址、端口（默认 445）、共享名称、共享内根目录。
- 域、用户名和加密密码。

### FTP/FTPS 字段

- 服务器地址、端口、根目录、用户名和加密密码。
- 被动模式开关和 TLS 开关；TLS 关闭时为 FTP，开启时为 FTPS。

协议不适用的字段必须为空。密码页面只写不回显；提交空密码表示保留已保存密码。连接凭据不进入任务快照、日志、异常文本、导出文件或终端脚本。

`ComputerAnalysisProfile` 只保留分析项目、规则阈值、并发数、告警策略和定时计划。现有扫描目录、已处理目录和失败目录由新来源配置替代。定时计划触发日志获取任务，并冻结分析配置和非敏感来源参数。

## 连接器边界

定义协议无关的连接器接口，至少提供：

- 测试登录及目录访问。
- 列出待处理文件的名称、大小和修改时间。
- 下载到指定本地临时文件。
- 获取下载前后的远端文件元数据。
- 在同一来源内移动到已处理或失败目录。
- 创建归档目录。
- 关闭连接。

SMB 和 FTP/FTPS 各自实现该接口。每个并发下载线程使用独立连接，避免共享非线程安全会话。所有协议错误映射为稳定的错误类别和脱敏中文提示。

“测试连接”必须验证登录、列表、下载以及同目录创建和移动临时探测文件的权限，并在结束时清理探测文件。“预览日志”只执行列表和筛选，不下载、不移动、不创建任务。

## 终端采集脚本

### Windows

以用户提供的 `TerminalLogs.ps1` 为采集主体，保留并整理以下信息：

- 计算机名、当前登录用户、安装日期、开机时间、Windows 版本、版本类型、详细版本和 BIOS 序列号。
- 活动网卡的 IP 与 MAC。
- CPU 型号、温度、占用率、频率、内存容量和内存使用率。
- Windows 激活与 KMS 连通状态。
- 域安全通道状态。
- 已安装软件、运行进程、BitLocker、Defender、最近更新、组策略和浏览器插件。
- 计算机名与登录工号匹配结果。

删除硬编码 DNS 到多个共享目录的映射，改为生成脚本时写入唯一的 `terminal_windows_path`。后台读取凭据不写入脚本；终端使用当前域计算机身份访问共享目录。

### macOS

保留现有 macOS 基础采集能力，写入管理员预先挂载的 `terminal_macos_path`。分析项目按平台能力区分，Windows 专属字段缺失不能自动变成 macOS 故障。

### 文件发布约定

- 正式文件名为 `<计算机名>-yyyyMMdd.json`。
- 先在目标目录写入唯一 `.uploading` 临时文件，写完并关闭后再发布为 `.json`。
- Worker 只发现 `.json`，忽略 `.uploading`。
- 同一天重复执行可替换尚未处理的当天文件。
- 当天日志已入库后再次出现时，作为重复日记录归档，不创建第二次默认分析。

## 数据模型

`ComputerLogFile` 增加：

- `computer` 明确外键。
- `collected_date`，按日志采集时间换算为系统时区的自然日。
- `platform`。
- `source_protocol`。
- `remote_source_path`。
- 日志来源配置的非敏感标识。

数据库约束保证同一 `computer` 和 `collected_date` 只有一份正式导入日志。内容哈希继续识别字节内容完全相同的重复日志。原始 JSON 保存在数据库中，后续重新分析不依赖远端文件。

新增持久化传输归档记录，至少保存：

- 远端源路径、目标归档路径和远端元数据。
- 本地暂存路径及内容哈希。
- `discovered`、`downloaded`、`imported`、`archive_pending`、`completed`、`failed` 等阶段。
- 关联日志、获取任务目标、尝试次数及脱敏错误。

该记录用于进程崩溃后恢复下载和远端归档，不能把临时网络错误误判为永久坏文件。

删除 `ComputerLogFile.upload_task`。日志与任务通过任务目标及传输记录关联。

## 任务模型与执行流程

原“计算机日志扫描”任务重命名为“PC 日志获取”。任务创建时绑定所选分析配置和全局日志来源的非敏感快照。

### 获取任务

1. Worker 领取任务租约。
2. 连接远端来源并列出 `.json`。
3. 按最近 N 天或指定起止日期筛选远端修改时间。
4. 排除 `.uploading`、归档目录和不合法路径。
5. 对候选文件进行有界多线程下载，每个线程独立连接。
6. 下载到本地唯一 `.part`，核对下载前后远端大小和修改时间。
7. 解析 JSON，验证计算机名和日志采集时间。
8. 刷新 PC 静态资产并保存 `ComputerLogFile`。
9. 持久化归档意图后，将远端文件移动到对应目录。
10. 为本次新导入的日志创建一个 PC 日志分析子任务。

获取任务详情显示发现、下载、导入、重复、失败、移动失败和待恢复数量，并可查看每个文件的阶段与错误。

### 分析任务

每个已导入日志是独立目标，由现有 Worker 线程池并行分析。任务使用创建时冻结的分析项目、阈值和告警策略。每次重新分析都创建新的 `ComputerAnalysis`，不会覆盖原始证据或历史结果。

### 手动结束

等待中或运行中的获取及分析任务均可手动结束。取消后不再提交新目标，数据库租约阻止旧 Worker 保存迟到结果。已经开始的 SMB/FTP 调用在协议超时后退出；未完成下载保留为临时文件并在恢复时清理或续传，远端源文件不移动。

## 文件分类和恢复

- 有效 JSON 成功写入数据库后进入远端 `processed/`。
- JSON 无法解析、缺少计算机名或缺少采集时间时，保存失败证据和原因，进入远端 `failed/`。
- 日志成功导入但规则分析发现异常时仍进入 `processed/`。
- 连接中断、文件在下载期间变化、数据库锁冲突或本地暂存失败时，远端文件留在原处，下次任务重试。
- 远端移动失败时使用持久化归档记录重试，不重复创建日志或分析。
- `processed/` 和 `failed/` 的目标文件名包含计算机名、采集日期和内容哈希片段，避免碰撞。

## 分析规则合并

保留当前 `net.devices.pc.analysis` 和 `checks` 作为正式分析入口，吸收旧 `tool.py` 的有效规则而不继续依赖旧模块。

已有规则继续配置化：软件白名单/黑名单、BitLocker、Defender 病毒库与扫描时间、补丁时效、Windows 最低版本、激活/KMS、开机时长、CPU和内存阈值。

增加对以下采集字段的分析与展示：

- 浏览器插件。
- 计算机名和登录工号匹配。
- CPU 温度和频率。
- 域安全通道状态。
- 组策略摘要。

旧 `analyze_log.py` 的并发读取由 Worker 线程池代替。旧 `pipeilog.py` 中的人员匹配、场地识别和 OU 核对进入数据库查询与页面/导出层：按工号匹配人员，使用已经同步的域账号、域计算机和 OU 数据，不在每条日志分析时重新连接 LDAP。场地/IP 规则应成为可配置映射，不能硬编码旧组织地址。

## 页面交互

PC 分析配置弹窗分为：日志来源、连接参数、终端投递路径、本地暂存、文件时间范围、分析项目、规则阈值、并发与定时、告警策略。弹窗内容可上下滚动。

主要操作：

- 保存配置。
- 测试连接。
- 预览日志。
- 下载 Windows 采集脚本。
- 下载 macOS 采集脚本。
- 手动执行分析。
- 结束活动任务。

测试和预览反馈使用页面弹窗；实际获取和分析在后台运行。预览显示远端文件名、大小、修改时间、推断计算机名、采集日期以及是否可能重复。

日志列表、分析记录、异常记录和任务详情继续支持筛选、排序、分页以及按筛选结果导出。

## 删除与迁移

- 删除 `/api/computer_inspection/` 路由和视图。
- 删除生成脚本中的 `upload_url` 和 HTTP 请求。
- 删除直接 API 上传专用测试、设置和关联字段。
- 删除旧本地扫描目录、已处理目录和失败目录字段，由远程来源配置和本地暂存目录替代。
- 将已有“计算机日志扫描”任务命名和代码迁移为“PC 日志获取”。
- 使用新迁移直接调整开发数据库结构；不编写旧业务数据搬迁脚本。

## 验收标准

- 页面能保存一套 SMB 或 FTP/FTPS 来源，并隐藏不适用字段。
- 测试连接验证登录、列表、下载和远端移动权限；预览不改变文件。
- Windows 和 Linux Worker 都能通过两种协议之一获取日志。
- Windows 和 macOS 下载脚本不包含 API URL 或后台读取密码。
- Windows 脚本产生的主要字段均能被分析器识别；macOS 不触发 Windows 专属缺失故障。
- 每台 PC 每天最多产生一份正式日志和一次默认分析。
- 手动和定时任务均能完成获取、导入、分析和远端归档。
- 损坏日志进入失败目录并显示原因；分析异常日志进入已处理目录。
- 下载、数据库或归档中断后可恢复且不重复生成记录。
- 获取和分析任务均可手动结束，取消后旧 Worker 不能写入迟到结果。
- PC 基本信息、人员工号、域账号、域计算机、OU 与场地可关联展示。
- 日志、分析和异常页面能筛选、分页并导出筛选结果。

## 测试策略

- 连接器契约测试覆盖 SMB、FTP和FTPS的列表、下载、元数据核对、移动、权限错误与连接中断。
- 使用内存或本地协议替身验证上层任务，不在单元测试中连接真实域控共享目录。
- 导入测试覆盖 BOM、非 JSON、非对象根节点、缺少字段、文件变化、同日重复和内容重复。
- Worker 测试覆盖并发上限、租约丢失、手动取消、子任务创建、重启恢复和归档重试。
- 分析测试使用 `TerminalLogs.ps1` 真实字段结构的脱敏样例，覆盖每个分析项目及 Windows/macOS 平台差异。
- 页面测试覆盖来源类型切换、密码保留、连接测试、预览、后台任务提示和导出。
- 删除 API 后增加路由测试，确保旧端点返回 404，生成脚本中不再出现 HTTP 上传逻辑。
