# 资产工作台、PC 脚本与域控操作设计

## 目标

在现有 Django 资产、巡检、分析与后台任务体系上增量扩展，完成首页信息架构调整、静态资产配置补充、统一巡检任务栏、Windows/macOS PC 采集脚本下载、域控账号与计算机批量操作、权限审计以及 Django 管理后台完善。

本次不重写现有资产和任务模型，不迁移历史数据，也不连接真实设备或真实域控做测试。新增字段允许为空，演示数据库通过幂等种子命令补充展示数据。

## 设计原则

- 复用现有 `TaskRun`、`TaskTargetRun`、巡检记录和计算机分析记录，不建立第二套执行流水线。
- 资产列表保存稳定的身份与硬件容量信息；CPU 使用率、内存使用率、磁盘利用率等动态数据只进入巡检或分析记录。
- 首页设备状态基于每台设备最近一次有效结果计算，不再限定为当天。
- 域控写操作必须同时通过页面权限和服务端权限校验，并进入后台任务和审计记录。
- 密码不进入普通任务快照、结果、日志、消息或审计内容。
- 目录调整只围绕本次新增职责进行，不移动现有 Django 模型模块，不做无关重构。

## 数据模型

### 人员

`People` 新增两个可空日期字段：

- `hire_date`：入职日期。
- `departure_date`：离职日期。

`is_active=True` 表示在职，`is_active=False` 表示离职。首页“离职人数”按 `is_active=False` 统计；日期为空不影响状态判断。CSV、飞书和钉钉同步适配器在来源提供日期时更新字段，来源未提供时保留现有值。

### PC

界面统一使用“PC”，内部模型名和既有 URL 保持兼容。`Computer` 增加可空静态字段：

- CPU 型号、物理核心数、逻辑处理器数。
- 内存总量。
- 磁盘总量和磁盘摘要。
- 设备厂商、设备型号、序列号、体系结构。

PC 列表和详情不展示 `is_active`。已有字段继续保存计算机名、操作系统、版本、构建号、IP、MAC、登录用户和最后上报时间。采集上传成功时更新静态硬件摘要；动态利用率仍保存在 `ComputerAnalysis`。

### 网络设备、服务器和安防设备

三类资产增加可空静态硬件摘要字段：CPU 型号、内存总量、磁盘总量。网络设备额外增加端口总数、启用端口数和 VLAN 数量。

导入模板、CSV 导入导出、详情页和 Django 管理后台支持这些字段。巡检采集到可信的容量或库存信息时允许更新对应资产字段；实时使用率只写巡检记录。

### 域控操作与敏感载荷

新增 `DomainOperation`，保存：操作类型、对象类型、发起人、状态、目标数量、参数脱敏摘要、任务关联、开始和结束时间。每个目标继续使用 `TaskTargetRun` 保存执行状态、目标 DN/标识和非敏感错误。

新增一次性敏感载荷模型，仅用于新增用户初始密码和重置密码。载荷使用部署环境提供的密钥加密，和域控操作一一关联；Worker 在事务中领取并解密到进程内存后立即删除数据库中的密文。领取前可沿用任务租约重试；领取后若进程中断，密码操作明确失败并要求管理员重新提交，不自动复用密码。任务快照、审计、异常消息和页面响应不得包含明文或密文。

## 首页信息架构

每个项目卡采用统一结构：标题、三项指标、上次执行时间、右下角操作区。

### 人员

- 人员总数。
- 在职人数。
- 离职人数。
- 详情和人员列表展示入职日期、离职日期。

### PC

- PC 总数。
- 正常设备：每台 PC 最近一次分析为成功且无异常。
- 异常设备：每台 PC 最近一次分析采集失败或存在异常。
- 未分析设备不计入正常或异常，卡片显示等待首次分析数量提示。
- 上次分析日期取所有 PC 分析记录的最新时间。
- “分析日志”和“手动执行分析”使用与基础设施巡检按钮一致的主操作样式。

### 网络设备、服务器和安防设备

- 设备总数。
- 巡检正常：最近一次巡检可达、采集成功且无异常。
- 巡检异常：最近一次巡检不可达、采集失败或存在异常。
- 未巡检设备不计入正常或异常，并显示等待首次巡检提示。
- 上次巡检日期取该类型全部巡检记录的最新时间。

### 域控管理

卡片标题改为“域控管理”。内容分为域账号和域计算机两列，各自展示总数、启用数和停用数，并提供进入管理页入口。

## 巡检任务栏

首页删除“最新巡检与分析记录”和“全部设备最新异常”两个独立区域，合并为“巡检任务栏”。数据源为执行型 `TaskRun`：设备巡检、PC 日志扫描和 PC 日志分析；人员同步、连接测试和域控管理任务不进入首页巡检栏。

任务栏每页 10 条，按创建时间倒序，保留查询参数并支持翻页。每行展示：

- 任务类型和巡检项目或分析配置名称。
- 手动或定时来源。
- 创建和完成时间。
- 设备/目标总数、正常数、异常数、等待或运行数。
- 任务总体状态。
- 任务详情入口。

目标“正常”定义为目标成功且结果记录正常；“异常”包括结果异常、部分成功和失败。等待、运行、取消单独计数，避免将未完成目标误判为正常。点击任务进入现有任务详情页，显示目标列表及统计；有结果记录的目标继续链接到巡检或分析详情。

## PC 脚本下载

分析配置页面提供“下载 Windows 脚本”和“下载 macOS 脚本”。下载时选择分析配置，服务端生成文本脚本并写入：

- 当前站点的异步上传 API 地址，优先使用显式部署配置的公开基础 URL，未配置时使用当前请求生成。
- 分析配置中的全部扫描目录；首个目录作为默认输出/上传日志目录。
- 分析项目和日志文件时间范围。

Windows PowerShell 脚本基于现有 `ps/GetInfo_JSON.ps1` 模板，采集系统、CPU、内存、磁盘、网络和日志文件元数据。macOS Shell 脚本使用系统自带命令采集同等信息，生成与现有异步接口兼容的 JSON 并上传。脚本不得嵌入后台账号、域控凭据或设备密码。

如果同一个配置中的路径无法同时用于 Windows 和 macOS，页面提示管理员分别建立两个分析配置。上传接口继续只负责校验和排队，分析由独立多线程 Worker 完成。

## 域控管理页面与权限

### 权限模型

新增 Django 权限 `net.manage_domain_operations`：

- 超级管理员自动拥有。
- 其他后台账号可通过用户或用户组授权。
- 无该权限的访问者沿用现有站点访问边界，只能查看域账号、域计算机及脱敏连接摘要。
- 域控连接设置、连接测试、同步和所有写操作都要求该权限。
- 已保存的绑定密码永不回显；空密码提交表示保留原值。

### 域账号操作

- 添加用户。
- 移动到 OU。
- 加入或移出安全组。
- 重置密码。
- 设置或取消“下次登录必须修改密码”。
- 设置或取消密码永不过期。
- 解锁账户。
- 启用或停用账户。

### 域计算机操作

- 移动到 OU。
- 加入或移出安全组。
- 启用或停用计算机账户。
- 当目录服务报告锁定且支持解锁时执行解锁。

账号和计算机共用批量操作框架，但服务端按对象类型维护动作白名单。页面根据选择对象展示可用动作；服务端不信任前端选项并再次验证。

### 执行与审计

提交前弹窗显示动作、目标数量和影响范围，并要求确认。确认后创建后台任务，Worker 逐个执行，允许多线程但对单个对象避免并发写冲突。批量任务部分失败时保留已成功操作并标记为部分成功；任务详情提供“仅重试失败项”。

LDAP 服务层封装连接、DN 规范化、OU/组解析、动作执行和错误归类。用户输入的 DN 必须位于配置的 `base_dn` 范围内。错误信息经过脱敏后进入目标结果和审计。

## Django 管理后台

管理后台注册并配置以下模型：

- 人员、PC、网络设备、服务器、安防设备。
- 域账号、域计算机、域控配置和域控操作审计。
- PC 日志文件、PC 分析、三类巡检记录及异常记录。
- 巡检配置、分析配置、调度、任务、任务目标。
- 告警配置、告警事件、告警发送记录。
- 人员同步源及相关集成配置。

列表提供有用的 `list_display`、搜索、筛选、日期层级和关联跳转。任务快照、执行结果、审计时间和系统生成标识设为只读；域控绑定密码及一次性敏感载荷不在普通管理列表中展示。

## 目录结构调整

保留 `net/asset_models.py`、`net/record_models.py`、`net/task_models.py` 和 `net/models.py`，避免模型包化导致 Django 重复注册或迁移漂移。新增代码按职责放置：

- `net/domain/`：LDAP 客户端、动作定义、权限与脱敏。
- `net/tasks/executors/domain.py`：域控后台任务执行器。
- `net/scripts/`：脚本模板和生成服务。
- `index/views/`：保持按 dashboard、domain、tasks、assets 分离。
- `index/templates/components/`：首页卡片、任务栏和域控批量操作组件。

部署脚本、终端采集脚本和文档分别保留在清晰的顶层目录；只移动能够通过导入、URL、文档和测试同时更新验证的文件。不为了目录美观移动稳定模块。

## 错误处理

- 首页统计查询失败不得伪造正常状态；页面显示可诊断错误并保留其他卡片。
- 脚本配置缺少扫描目录时拒绝生成，并提示先完成分析配置。
- 域控连接失败、对象不存在、DN 越界、组或 OU 不存在、权限不足分别记录可理解的错误。
- 密码解密失败时任务失败并清除敏感载荷，不在错误文本中输出密码或密文。
- Worker 中断后沿用现有租约恢复机制；已完成目标不重复执行，失败目标可显式重试。

- 未登录、只读用户、授权用户、超级管理员四类域控权限测试。

- 验证密码不出现在任务快照、页面、日志、消息、审计和导出中。
- Django admin 模型注册、搜索与只读字段测试。
- 运行完整 Django、JavaScript、系统检查、迁移漂移和依赖检查。

验收完成时，原始生产数据库文件保持不变；展示数据只写入独立演示数据库。
