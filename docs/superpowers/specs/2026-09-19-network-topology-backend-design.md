# 网络物理拓扑后端设计

## 目标与边界

在现有网络设备巡检体系内实现真实物理拓扑。管理员在巡检模板和巡检设置中选择“拓扑发现（LLDP/CDP）”，通过现有手动巡检或计划任务执行。后端保存发现批次、接口、当前链路和不可变证据，并向综合展示页提供认证只读数据。

只有 LLDP/CDP 明确证据可以生成物理链路；不得根据同网段、ARP、MAC/FDB、相同 VLAN 或相似名称推测链路。名称只用于唯一候选的辅助解析，冲突时保留未解析端点。连续未发现的链路标记陈旧，不立即删除。

## 接入现有巡检

项目已有 `InspectionProfile`、`Schedule`、`TaskRun`、`TaskTargetRun`，以及 SNMP/SSH/混合网络采集器。内部项目键继续使用现有 `lldp_neighbors`，显示名称改为“拓扑发现（LLDP/CDP）”，避免破坏已有模板和巡检配置。

该项目支持：

- `snmp`：读取标准 LLDP-MIB。
- `ssh`：执行厂商模板中的 LLDP/CDP 只读命令。
- `auto`：优先 SNMP；有 SSH 配置时补充 SSH LLDP/CDP。SNMP 失败但 SSH 证据完整时仍可完成项目。

华为、华三、锐捷、思科基础模板保留并完善现有命令和解析器，拓扑项目默认使用 `auto`。类型模板和设备覆盖继续使用现有继承规则。管理员可创建只含拓扑项目的巡检设置，再通过现有计划任务配置 30–60 分钟周期；不新增调度器，也不自动修改已有计划。

## 数据模型

### TopologyDiscoveryBatch

每个网络设备的拓扑项目执行产生一个批次：

- 关联来源 `TaskRun`、`TaskTargetRun` 和网络设备。
- 同一 `TaskTargetRun` 最多一个批次，保证 Worker 重试幂等。
- 协议为 `snmp_lldp`、`ssh_lldp`、`ssh_cdp` 或 `mixed`。
- 状态为运行中、成功、部分成功、失败或取消。
- 保存结构版本、开始/采集/结束时间、安全说明和接口、观察、解析、冲突数量。

### NetworkTopologyInterface

保存设备当前接口：设备、稳定接口键、可选 ifIndex、名称、描述、标准化 MAC、管理/运行状态、速率、VLAN ID 列表、首次/最后发现时间、最近批次和陈旧状态。

唯一约束是“设备 + 稳定接口键”。稳定键依次使用 `ifindex:<值>`、`mac:<值>`、`name:<规范化名称>`。同批 SNMP/SSH 接口按 ifIndex、MAC、规范化名称逐级合并；多个候选时不合并并记录冲突。

### NetworkTopologyLink

保存当前物理链路：稳定链路键、本地接口、可选远端设备/接口、远端 chassis/port/system/管理地址、协议来源、单侧或双向证据、解析状态、当前或陈旧状态、速率、VLAN、可信度、首次/最后发现、最近批次及连续缺失次数。

已解析链路以排序后的两个端点生成稳定键，两端发现时合并为一条；未解析链路以本地接口、协议和远端 chassis/port 生成键。失败、取消和部分批次不增加缺失次数。只有同一设备连续两个完整成功批次未发现链路时才标记陈旧；重新发现后恢复。系统不自动删除链路。

### NetworkTopologyObservation

每条邻居观察保存为不可变证据：批次、来源目标、本地设备/接口、协议、标准化邻居字段、已脱敏且最多 64 KiB 的来源证据、完整脱敏证据 SHA-256、采集时间和可选链路引用。

业务代码不更新观察，也不提供修改接口。同批次摘要唯一，重试不重复写入。证据保留 90 天后由现有维护流程小批量清理；当前接口和链路不随证据过期而删除。

## 采集与解析

SNMP 增加 LLDP-MIB 本地端口表、远端邻居表和管理地址表，至少得到本地端口、远端 chassis ID、port ID/描述、system name 和管理地址。使用数字 OID，不要求部署外部 MIB 文件，并沿用现有总超时、重试、行数和大小限制。

SSH 使用模板中的只读命令。解析结果必须包含本地接口，以及至少一个远端 chassis、port、system 或管理地址字段，否则只记录采集问题，不生成链路。“完整空表”与请求失败、超时、解析未匹配严格区分。

## 端点匹配与可信度

远端设备按以下顺序匹配：

1. chassis MAC 与已知接口 MAC 唯一匹配。
2. 管理地址与网络设备 IP 唯一匹配。
3. system name 与设备名或最近系统名唯一匹配。

任一步出现多个候选即标记冲突，不继续弱匹配。无法匹配时保留未解析端点。

可信度规则固定且可解释：双向互证 1.00；单侧且设备与接口唯一解析 0.85；只解析到设备 0.70；有效证据但未解析 0.60；冲突 0.25。它表示证据完整度，不表示链路质量。

## Worker 与事务

网络请求、模板解析、规范化、脱敏和摘要计算全部在事务外完成。写入前再次检查取消状态和租约，然后在短事务中幂等写入批次、接口、观察和链路。

拓扑落库失败时仍保存其他巡检结果，但拓扑项目和目标不能显示完全成功，任务详情给出安全、可排障原因。部分成功可以刷新有效链路，但不能推进旧链路的缺失次数。普通巡检详情只保存拓扑摘要，不重复保存完整证据。

## 认证只读 API

所有接口只接受 GET，要求登录，并在 SQL 层分页、过滤和排序：

- `/operations/topology/data/`：当前物理拓扑。
- `/operations/topology/batches/`：发现批次。
- `/operations/topology/interfaces/`：接口。
- `/operations/topology/links/`：当前和陈旧链路。
- `/operations/topology/evidence/<uuid>/`：证据详情。

综合展示的 `/operations/overview/data/` 复用同一序列化服务，在 `topology` 中返回 `kind: physical_discovered` 链路；没有真实数据时继续显示逻辑拓扑。

普通接口显式输出白名单，不包含采集证据、连接参数、凭据或异常堆栈。证据详情需要新增 `net.view_topology_evidence` 权限；超级用户自动具备，staff 管理员需显式授予，普通用户默认不具备。即使具有权限，也只能读取已脱敏、限长证据。证据接口禁止缓存；拓扑更新后使综合展示权限隔离缓存失效。

## 迁移与影响

新增四类模型、索引和证据权限需要数据库迁移。迁移只建表和权限，不连接设备、不修改历史巡检记录。旧 `lldp_neighbors` 配置继续有效；首次成功执行后才产生拓扑数据，不从历史 JSON 猜测链路。

部署需要应用迁移并重启 Web/Worker，不需要重置数据库。

## 测试与验收

使用隔离数据库和伪造响应覆盖：

1. SNMP LLDP 正常、完整空表、分页、超时和畸形数据。
2. 四个默认厂商 SSH LLDP/CDP 样例。
3. SNMP、SSH、自动方式分配和现有模板继承。
4. 接口稳定键、协议间合并和冲突。
5. chassis、管理 IP、唯一名称解析及冲突不猜测。
6. 单侧/双向链路、可信度、幂等重试。
7. 两次完整缺失后陈旧；失败、取消、部分结果不推进陈旧。
8. 事务范围、取消/租约检查和落库失败说明。
9. 登录、字段白名单、分页、证据权限和缓存失效。
10. 综合展示优先真实链路，无数据时保留逻辑拓扑。
11. Django 检查、迁移漂移、相关回归和完整测试。

真实环境仍需选择至少一台可返回 LLDP 的设备和一对互联设备验证；模拟通过不等于真实设备已验证。

## 非目标

不推测物理链路，不修改设备 LLDP/CDP 配置，不实现配置下发、流量路径计算或网络变更，也不把完整证据重复写入普通巡检 JSON。
