# 网络巡检中心任务、告警与记录体系重构设计

## 目标

把现有网络巡检中心重构为静态资产、动态巡检或分析日志、后台任务、告警和第三方同步边界清晰的系统。人员和设备列表只保存及展示基本资料；CPU、内存、温度、磁盘、服务、接口等动态结果进入独立巡检记录；计算机动态数据统一称为“分析日志”。系统部署在一台长期在线的 Windows Server 或 Linux 服务器上，由独立多线程 Worker 执行手动任务和定时任务。

本次按全新数据结构建设。旧业务数据、旧任务记录和旧巡检记录不保留，不编写数据转换或回填逻辑。Django 结构迁移用于创建最终模型；开发和正式部署均从空数据库初始化，并通过演示数据命令生成可完整展示的样例。

## 已确认范围

- 列表导入和导出分离；原“数据工具”改名为“导入”。
- 导出入口放入紧凑筛选工具栏，并导出当前全部筛选结果，而不是只导出当前分页。
- 筛选控件按字段类型和实际数据生成下拉、建议列表、布尔选项及范围控件。
- 人员、计算机、网络设备、服务器、安防设备的静态列表和动态记录页面分离。
- 每个人员、设备、巡检记录和计算机分析日志都有独立详情页。
- 计算机不再使用“巡检”文案，统一称为“分析日志”；手动分析只分析服务器已导入的 PowerShell JSON 日志，不远程控制终端。
- 网络设备、服务器、安防设备保留类型级执行按钮，统一命名为“手动执行巡检”。
- 定时任务仅支持“每隔 N 分钟/小时”和“每天指定时间”两种计划。
- 后台 Worker 跨 Windows 和 Linux，支持可配置线程池并发，不要求 Redis。
- 告警支持飞书、钉钉和邮件多选；项目可继承默认设置或覆盖设置。
- 每次异常执行都发送告警；异常状态恢复后发送恢复通知；不增加告警冷却时间。
- 人员支持 CSV、飞书 API、钉钉 API 导入；API 同步以工号匹配，同来源缺失人员标记停用。
- 网络设备和安防设备支持单台及筛选结果批量导出设备配置。
- 计算机日志从可配置的服务器目录扫描，按文件最后修改时间限制最近 N 天或指定起止日期。

## 总体架构

采用“Django Web + 数据库任务队列 + 独立多线程 Worker”架构。

- Django Web 负责资产维护、筛选导出、创建手动任务、配置计划、展示进度、记录详情和配置第三方连接。
- 数据库保存调度计划、任务实例、目标子任务、巡检或分析结果、告警状态及发送记录。
- `run_task_worker` 管理命令作为独立常驻进程运行，轮询到期计划和等待任务，通过线程池执行 I/O 密集型 SSH、HTTP、文件扫描、日志分析、API 同步和告警发送。
- Windows Server 使用服务包装器注册 Worker 管理命令；Linux 使用 systemd 单元运行同一命令。
- 数据库领取任务时使用事务、状态条件和任务租约防止重复执行。Worker 异常退出后，租约超时的任务回到可领取状态。
- 全局并发数和单个配置并发数均可设置；实际并发取二者较小值。相同配置和相同目标范围已有运行中任务时拒绝重复提交。

生产环境使用项目现有 MySQL 配置。SQLite 仅用于开发和自动化测试，避免多线程 Worker 持续写入时产生数据库写锁竞争。

## 数据模型

### 静态资产

保留并重新整理现有人员及资产模型名称，删除不再需要的旧任务兼容关系。

- `People`：姓名、工号、邮箱、部门、负责人、启用状态、数据来源、平台用户 ID、最后同步时间。
- `Domain_Account`、`Domain_Computer`：继续由域控同步，并提供独立详情页。
- `Computer`：计算机名、IP、MAC、系统名称、系统版本、构建号、安装时间、最后上报时间、启用状态等静态或低频信息。
- `Network_Device`：名称、IP、设备类型、型号、厂商、连接方式和连接参数。
- `Server`：名称、IP、服务器类型、操作系统和 SSH/HTTP 连接参数。
- `Monitor`：名称、IP、设备类型、型号、厂商和 API 连接参数。

连接密码、API Token、机器人密钥和 SMTP 密码不进入表格注册、CSV 导出、配置 ZIP、普通日志或错误详情。

### 配置和调度

- `InspectionProfile`：设备类型、名称、启用状态、默认巡检项目、目标选择规则、单设备超时、并发数和告警策略。
- `ComputerAnalysisProfile`：名称、日志扫描目录、是否递归、归档目录、失败目录、文件时间模式、最近天数或起止日期、分析项目、并发数和告警策略。
- `Schedule`：关联巡检或分析配置，类型为间隔或每日，保存间隔数值/单位或每日执行时间、启用状态、下次执行时间和上次创建任务时间。
- `TaskRun`：任务类型、来源（手动或定时）、配置、状态、进度、创建/开始/完成时间、租约、Worker 标识、错误摘要和参数快照。
- `TaskTargetRun`：关联任务与具体设备或日志文件，保存状态、尝试次数、开始/完成时间、结果引用和错误。

任务状态固定为等待、运行、成功、部分成功、失败和取消。计划只创建 `TaskRun`，实际执行由 Worker 完成，Web 请求不等待采集结束。

### 动态记录

- 网络设备、服务器、安防设备各自保留专用巡检结果模型，保存采集时点、可达性、采集状态、耗时、动态指标、原始响应和关联 `TaskTargetRun`。
- `ComputerLogFile` 保存原始日志文件路径、文件修改时间、大小、内容哈希、导入状态、解析错误和归档路径；内容哈希用于避免重复导入。
- `ComputerAnalysis` 保存某个已导入日志的分析时间、选中的分析项目、状态、摘要、结构化结果、异常项和关联 `TaskTargetRun`。
- 每一条巡检和分析记录都有独立详情路由；列表页支持独立筛选、排序、列偏好和导出。

### 告警和同步

- `AlertChannel`：渠道类型、名称、启用状态和飞书机器人、钉钉机器人或 SMTP 配置。
- `AlertPolicy`：默认或项目级策略，关联一个或多个渠道；项目可选择继承全局默认或覆盖。
- `AlertState`：按项目、目标和异常类别记录最近状态，用于判断首次异常、持续异常及恢复。
- `AlertEvent`：关联任务、目标、巡检或分析记录，保存异常/恢复类型、合并消息、发生时间和总体状态。
- `AlertDelivery`：每个事件每个渠道一条发送记录，保存尝试次数、响应摘要、成功时间和失败原因。
- `PeopleSyncSource`：飞书或钉钉的应用凭据、部门范围、启用状态、最近测试及同步结果。

## 页面信息架构

### 首页

每个子项卡片将静态入口和动态入口分开：

- 人员：人员列表、API 导入。
- 计算机：计算机列表、分析日志。
- 网络设备：设备列表、巡检记录、手动执行巡检。
- 服务器：服务器列表、巡检记录、手动执行巡检。
- 安防设备：设备列表、巡检记录、手动执行巡检。
- 域控：域账号、域计算机、立即同步。

首页保留全局最近动态和异常摘要，但不承担完整筛选。网络设备、服务器和安防设备的“手动执行巡检”按钮保留；计算机对应按钮为“手动执行分析”。

### 静态列表和详情

静态列表只显示基本资料。CPU、内存、温度、磁盘、服务、接口、通道等动态字段不再出现在设备基本列表。

- 人员详情展示人员资料、来源和同步信息。
- 计算机详情展示静态信息、最近上报时间及进入分析历史的入口。
- 网络设备、服务器、安防设备详情展示基本信息、连接方式摘要、最新巡检摘要、巡检历史入口和单台配置导出。
- 域账号和域计算机拥有独立详情页。

### 巡检和分析页面

- 每个基础设施类型拥有独立巡检记录页，另保留全局全部巡检和全部异常页。
- 计算机使用独立“分析日志”列表和“分析详情”，不出现“计算机巡检”文案。
- 记录列表显示时间、目标、执行结果、关键动态指标、异常数、任务来源和详情入口。
- 巡检、分析和告警列表都支持筛选结果导出。
- 页面右上角放置“手动执行巡检/分析”和“巡检配置/分析配置”；告警配置入口与执行按钮并列。

## 紧凑筛选、导入和导出

### 筛选工具栏

统一表格注册增加筛选控件类型和选项来源：

- 布尔、固定状态和枚举字段使用下拉框。
- 厂商、类型、部门、操作系统等低基数字段从当前模型去重生成下拉选项，设置最大选项数并按显示值排序。
- 名称、IP、MAC、工号等高基数字段使用可搜索建议列表，仍允许手动输入精确或包含值。
- 日期、时间和数值使用起止范围。
- 常用筛选在一行紧凑展示，其余字段放入“更多筛选”折叠区。
- 用户仍可在浏览器中保存显示列、启用筛选字段和每页数量偏好。

筛选参数必须经过字段注册白名单和类型校验。下拉选项查询不包含凭据字段，并限制返回数量，避免大表加载全部不同值。

### 导入

原“数据工具”按钮改为“导入”，弹窗不再包含普通数据导出。

- 人员：CSV 模板/导入、飞书 API、钉钉 API。
- 网络设备、服务器、安防设备：CSV 模板/导入。
- 计算机：不提供人工资产导入；数据来自日志目录扫描。
- 域账号和域计算机：不提供导入；数据来自域控同步。

人员 API 导入先测试连接并显示同步预览，再确认同步。以工号作为唯一业务匹配键；新增或更新本次返回人员，只把同一来源中未返回的人员标记停用。CSV、手工、飞书和钉钉来源互不误停用。

### 筛选结果导出

“导出筛选结果”位于筛选工具栏右侧，复用经过验证的当前查询状态。服务端重新执行完整筛选和排序，不使用当前分页对象。静态列表、巡检记录、分析日志、告警记录和域对象均使用统一导出适配器。

网络设备和安防设备另外提供配置导出：

- 详情页下载单台设备最近一次成功采集的原始文本或 JSON 配置。
- 列表页按当前筛选结果生成 ZIP，每台设备一个文件，并附带清单说明成功、缺失和厂商 API 不支持的设备。
- 网络设备配置来自 SSH 巡检的配置结果；安防设备配置来自厂商适配器。适配器明确返回支持、不支持或失败状态。
- 配置文件和 ZIP 不包含系统保存的登录密码、Token 或机器人密钥。

## 手动执行和定时执行

### 基础设施巡检

点击“手动执行巡检”打开弹窗，可选择全部设备、勾选设备或当前筛选结果，选择本次巡检项目，并选择默认或临时并发数。提交后创建 `TaskRun` 和目标快照，页面跳转至任务详情或显示后台执行提示。

“巡检配置”管理默认巡检项目、目标规则、单设备超时、并发数、计划和告警策略。不同设备类型通过巡检项目注册表只显示适用项目。

### 计算机日志扫描和分析

`ComputerAnalysisProfile` 支持配置一个或多个服务器目录，并按文件最后修改时间选择：

- 最近 N 天；或
- 指定开始、结束日期。

Worker 可递归扫描子目录。符合范围的 PowerShell JSON 文件通过内容哈希去重，成功导入后移动到配置目录下的 `processed`，解析失败移动到 `failed`，并记录成功、跳过、重复和失败数量。目录必须解析为允许的绝对路径；系统不得移动扫描根目录之外的文件。

“手动执行分析”可以扫描配置目录并分析新日志，也可以从日志文件详情重新分析已导入文件。分析配置定义需要执行的分析项目、文件时间范围、并发数、计划和告警策略。

### 调度

计划只支持：

- 每隔 N 分钟或小时；
- 每天指定本地时间。

Worker 每轮在数据库中领取到期计划并创建任务。计划保存参数快照，后续修改不会改变已经创建的任务。系统显示下次执行、上次执行、最近结果和启停状态。

## 告警

### 渠道

- 飞书使用自定义机器人 Webhook 和可选签名密钥。
- 钉钉使用群机器人 Webhook 和可选加签密钥。
- 邮件使用 SMTP 主机、端口、TLS/SSL、账号、密码、发件人和多个收件人。
- 每个渠道提供测试发送，结果写入审计记录。
- 一个策略可同时选择多个渠道。

### 触发和恢复

- 每次巡检或分析发现异常均创建并发送异常告警，不增加冷却时间。
- 同一次任务、同一目标的多个异常合并成一条结构化事件，再向选中的各渠道发送。
- 上一次状态异常、本次正常时创建恢复事件并发送恢复通知。
- 告警失败不改变巡检或分析结果；发送失败保存在 `AlertDelivery`，允许后台有限次数重试。
- 告警列表和详情展示关联目标、任务、异常摘要、恢复状态及各渠道结果，并支持筛选和导出。

## Worker 模块边界

- `net/tasks/models.py` 或等价模型模块：计划、任务、目标执行和租约状态。
- `net/tasks/worker.py`：领取、续租、线程池调度、任务状态汇总和崩溃恢复。
- `net/tasks/executors/inspection.py`：调用现有 SSH、Windows HTTP 和安防 API 采集器。
- `net/tasks/executors/computer_analysis.py`：目录扫描、归档、JSON 导入和分析。
- `net/tasks/executors/people_sync.py`：飞书和钉钉通讯录适配器。
- `net/alerts/`：策略解析、状态迁移、消息构建和飞书/钉钉/SMTP 发送器。
- `net/exports/`：筛选结果 CSV 和设备配置 ZIP。
- `index/table_registry.py` 与 `index/table_query.py`：字段元数据、选项来源、白名单筛选和排序。
- `index/views/`：按资产、记录、任务、配置、告警和同步拆分视图，避免继续扩大单个 `views.py`。

具体目录可在实施计划中按 Django 应用现状选择，但上述职责不得重新混入一个大型视图文件或一个大型管理命令。

## 错误处理和安全边界

- 任务目标失败只影响该子执行；任务汇总为部分成功或失败，并保留错误详情。
- 第三方 API 分页、限流、超时和暂时错误使用有限重试；凭据错误直接停止该同步任务并提示重新配置。
- 文件扫描拒绝不存在、不可读和越过配置根目录的路径；移动文件前验证解析后的绝对路径。
- 配置导出缺失时写入 ZIP 清单，不使用空文件冒充成功配置。
- 筛选导出使用与页面相同的字段白名单，且不导出密码、密钥和 Token。
- 告警渠道失败不阻断巡检；每个渠道单独记录结果。
- Worker 使用幂等任务状态和目标唯一约束，避免租约重领后重复生成巡检、分析或告警记录。

## 实施阶段

### 阶段一：页面和记录边界

重建静态资产与动态记录模型，拆分列表/巡检/分析页面，增加全部详情页，改造紧凑筛选、动态选项、导入弹窗和筛选结果导出。

### 阶段二：任务和调度

建立配置、计划、任务和目标执行模型，完成多线程 Worker、手动执行、间隔/每日计划、计算机目录扫描和分析配置。

### 阶段三：告警

完成默认/项目告警策略、飞书/钉钉/SMTP 发送器、异常合并、恢复判断、发送记录和告警页面。

### 阶段四：第三方同步和配置导出

完成飞书/钉钉人员同步预览与执行、同来源停用逻辑、网络/安防单台与批量配置导出、跨平台服务示例和最终演示数据。

每个阶段结束时系统必须保持可运行，自动化测试和浏览器验收通过后再进入下一阶段。

## 测试与验收

开发采用测试先行。自动化测试至少覆盖：

- 静态列表不出现动态指标，动态记录保留并正确关联详情。
- 每种人员、设备、域对象、巡检、分析、任务和告警详情路由。
- 下拉选项去重、选项上限、高基数建议、非法参数回退和浏览器偏好兼容。
- CSV 导出完整复用当前筛选和排序且不受分页限制。
- 配置 ZIP 按筛选目标生成清单，并排除所有凭据。
- 手动任务目标快照、重复任务拦截、租约领取、租约超时恢复和线程并发限制。
- 间隔计划和每日计划的下次执行计算及重启恢复。
- 日志文件最近 N 天和指定日期范围、递归扫描、哈希去重、成功归档、失败隔离和路径边界。
- 计算机手动重新分析已导入日志。
- 每次异常告警、同次异常合并、异常恢复、多渠道部分失败和有限重试。
- 飞书/钉钉 API 分页同步、按工号更新、同来源缺失停用及跨来源隔离。
- 演示数据命令可重复执行且不会触发外部请求。

浏览器验收覆盖桌面和窄屏：

- 首页每个子项的列表、巡检或分析入口以及手动执行按钮。
- 紧凑筛选、更多筛选、动态下拉、建议输入、排序、分页和筛选结果导出。
- 导入弹窗、人员 API 预览、任务进度、计划配置和告警配置。
- 每类详情页、单台配置下载、批量 ZIP 反馈和不支持状态。
- 告警事件、恢复事件及多渠道发送结果。
- 窄屏无页面级横向溢出，数据表在自身容器滚动，控制台无 JavaScript 错误。

## 非目标

- 不实现向计算机终端远程下发 PowerShell 执行任务或常驻终端 Agent。
- 不支持 Cron 表达式、每周或更复杂日历计划。
- 不增加告警冷却时间。
- 不引入 Redis、Celery 或多服务器分布式调度。
- 不迁移、回填或保留旧业务数据。
- 不在本阶段增加完整的用户权限和多租户系统。
