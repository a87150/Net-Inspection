# 网络巡检中心前端统一改造设计

## 目标

在不改变后端业务逻辑、模型、路由、接口与数据处理流程的前提下，把现有 Django + Bootstrap 界面统一为现代、简洁、专业的企业运维后台。全部页面、按钮、筛选、排序、分页、导入导出、巡检、日志分析、域控管理和后台任务流程继续可用。

## 现状与边界

- 所有主要页面继承 `index/templates/common/base.html`，本地 Bootstrap 与应用样式分别位于 `static/vendor/bootstrap/` 和 `static/app/`。
- 资产、域对象、记录页面共享 `common/table_workspace.html`、筛选、分页与原生 JavaScript 偏好持久化。
- 长配置弹窗、人员 API 导入、域操作与告警均已有服务端表单和 `data-*` 交互契约；这些名称、动作 URL、字段和值不可改变。
- 不添加在线字体、图片、图标库或大型前端框架；视觉标记使用 CSS 与文本。
- 测试不得调用真实飞书、钉钉、域控或设备接口，不执行真实导入和巡检。

## 设计方向

采用偏冷静的蓝灰企业后台视觉。页面背景、表面、边框、文字、主色以及成功、警告、危险、运行中和停用状态由 CSS 令牌统一管理；字体使用跨 Windows/Linux 的系统字体栈。卡片降低装饰性、提高信息密度，标题、说明、主要动作和次要动作形成稳定层级。

不重做信息架构。顶部导航保留现有入口和路由，通过更清晰的品牌区、下拉层级、当前交互反馈和窄屏布局提高可用性。首页继续展示人员、PC、网络、服务器、安防和域控六类状态，并强化总览区、卡片指标层次与任务区，使操作员从上到下完成“看资产健康—看待处理状态—进入任务”的扫描。

## 公共组件

- 页面标题：统一 eyebrow、主标题、描述和动作区，动作在窄屏自动换行。
- 数据表：统一表头、数字可读性、行悬停、长文本换行、横向滚动提示、固定表头和固定操作列。表格容器获得明确区域标签与键盘焦点。
- 筛选区：作为独立控制面板展示，关键字和常用条件优先；更多筛选与自定义表格使用可展开区；结果摘要、每页数量和分页形成一组。
- 状态：继续保留可读文本，并以图形标记、颜色和边框三重表达。成功/正常为绿色，运行中/信息为蓝色，警告/部分成功为琥珀色，异常/失败为红色，停用/未运行为灰色。
- 详情：基础资料、执行摘要、错误与原始数据使用一致卡片和 definition list 网格；长 JSON/日志内部滚动。
- 弹窗：所有弹窗限制在视口内，正文独立纵向滚动，标题和操作区始终可见；长配置按逻辑小节分组，移动端按钮纵向排列。

## 响应式与可访问性

- 桌面表格优先保持信息密度；窄屏通过横向滚动而不是压缩列宽，操作列保持可见。
- 小屏页面动作、筛选字段和弹窗按钮占满可用宽度；仪表盘由三列逐步降到两列和一列。
- 保留跳转主内容链接、可见焦点、语义标题、表格区域标签和 modal label。状态必须包含文字，不允许只用颜色。
- 尊重 `prefers-reduced-motion`，颜色对比满足基本可读性要求。

## 验证策略

先增加界面契约测试并确认其因新设计钩子缺失而失败，再分阶段实现。每阶段运行相关 Django 测试和 Node 原生 JavaScript 测试；最终运行 `manage.py check`、模板覆盖测试、全部 Django 测试、全部前端测试以及迁移检查。只使用测试数据库和 mock/fixture，绝不触发真实外部连接或设备动作。
