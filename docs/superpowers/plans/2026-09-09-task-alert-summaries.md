# 任务汇总告警实施计划

**Goal:** 每个巡检/日志分析任务结束后，每个配置渠道仅投递一条任务总结；管理员可配置精简/详细及自定义模板。

**Architecture:** 保留逐设备异常恢复事件用于站内审计，不创建逐设备投递。Worker 完成目标告警状态处理后，幂等创建任务总结及投递记录，复用现有重试租约。总结冻结数据和渲染文本；模板修改不影响重试。

**Tech Stack:** Django、MariaDB/SQLite、现有后台 Worker 和告警适配器。

## 约束与设计

- 所有新巡检和 PC 日志分析任务（包含成功、部分失败、失败、取消）结束后汇总。PC 获取日志父任务不与分析子任务重复发送，父任务失败才总结。
- 等待所有已结束目标的告警状态处理成功，避免丢失恢复信息；没有外部通知通道也记明确状态。
- 每任务唯一 summary 事件、每事件每渠道唯一投递。未完成任务不发半份总结。
- 统计分开描述执行失败和业务异常，恢复可与异常重叠；提示项不算异常。摘要限制条数，详情留在任务页面。
- 管理员模板弹窗，POST 保存和预览，白名单变量替换，不执行模板代码。正常任务也通知。
- 迁移标记既有终态任务为已处理，不补发历史；旧未发设备投递停止，保留历史审计。
- 不调用真实通知 API 作测试，不提交无关文件。
