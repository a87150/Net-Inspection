# 设备原始配置备份

## 使用

网络设备执行巡检时自动增加设备配置采集，不必在巡检项目里单独勾选。按北京时间，每台设备每天第一次成功采集并保存的配置形成一个版本。当天后续巡检复用该版本；当天失败可以在后续巡检重试。没有执行巡检的日期不会凭空生成备份，请在巡检配置中设置每日定时执行。

每台设备只保留最近 **10 个成功日版本**，即使相邻日期配置相同也分别保存。第 11 份成功保存时才删除最早一份，失败不会覆盖或清理已有版本。过期版本会从数据库删除，需要长期保留时提前下载。

管理员进入网络设备或安防设备详情 → **配置备份历史**，可以查看日期、采集时间、大小、SHA-256、来源任务，并选择某一份下载。原有配置下载入口下载最新成功版本，列表的配置 ZIP 导出下载筛选设备的最新成功版本；无备份的设备在 ZIP 清单中注明。

下载文件保留采集到的原生配置内容，不替换密码、不添加提示行、不包装 JSON。普通巡检记录仅保存备份元数据，不含原文。历史页不展示密码原文，普通用户和游客不能下载配置或查看备份历史。

## 支持范围和恢复注意事项

- Cisco：通过 SSH 获取 `show running-config`。
- H3C：通过 SSH 获取 `display current-configuration`。
- SNMP 继续采集动态指标，配置采集仍需要 SSH 凭据和读取配置的权限。
- 仅接受完整命令结束标记、无分页和命令报错的原生当前配置。脚本仅剥离会话提示符、命令回显，不对配置内容脱敏或改写换行。
- 当前配置文件不是整机镜像，不包含单独保存的启动配置、固件、证书私钥和其他文件。设备本身不返回的秘密无法通过本系统还原。恢复方式、固件与型号兼容性需要按厂商文档确认；系统不自动执行恢复。
- 当前大华接口只导出 Network 局部配置，**不能用于整机恢复，因此不会进入完整备份历史**。需要对应品牌型号的原生整机备份接口才能增加支持。旧的脱敏巡检快照无法还原成原始备份，必须重新巡检。

## 密钥与部署

配置原文用独立 Fernet 密钥加密存入数据库，下载时解密并验证 SHA-256 和字节长度。Web 与 Worker 必须使用同一个稳定密钥。

可选方式：

- 环境变量 `DEVICE_BACKUP_ENCRYPTION_KEY`。
- `DEVICE_BACKUP_ENCRYPTION_KEY_FILE` 指向密钥文件，相对路径从项目根目录解析。文件仅允许服务账户读取。
- Windows 使用 `DEVICE_BACKUP_KEYRING_SERVICE` 指定系统凭据管理器中的服务名，用户名固定为 `device-backups`。当前部署使用 `net-inspection-device-backups`，不将密钥写进仓库或 `.env`。

密钥必须另行妥善备份。只有数据库备份而没有原密钥将无法解密配置；更换服务账户、迁移服务器前必须转移原密钥，不要重新生成覆盖已有密钥。密钥损坏或丢失时下载会拒绝，不输出伪造或不完整配置。

执行 `python manage.py migrate` 创建 `DeviceConfigurationBackup` 表，重启 Web/Worker 后生效。版本写入和清理在设备行锁及事务内执行；巡检写入受任务租约保护，取消或丢失租约会回滚同次备份。
