# Final Branch Review

审查范围：`e751355..3b94985`

结论：**暂不批准合并/部署**。发现 3 个 Important、1 个 Minor，均可由当前代码路径直接确认；未发现可确认的 Critical。

## Important

### 1. 新增域用户不是可重试操作，密码设置失败后会留下无法由“仅重试失败项”恢复的半成品账号

- 位置：`py/net/net/domain/client.py:113-128`，`py/net/net/tasks/domain.py:286-324`
- 现象：`create_user` 先调用 LDAP `add`，成功后再单独修改 `unicodePwd`。如果用户已经创建、但密码修改因密码策略、权限、网络中断或超时失败，目标会被记录为失败；随后“仅重试失败项”会重新执行完整 `create_user`，再次从 `add` 开始，并因对象已存在而失败，永远到不了密码设置步骤。
- 影响：AD 中留下未完成初始化的账号，任务审计显示失败，页面提供的标准重试流程无法修复；超时场景还可能无法判断第一次 `add` 是否已在 AD 生效。
- 修复建议：把新增用户实现为可恢复的分阶段操作。至少应在重试时查询目标 DN，只有在可验证其身份与本次请求一致时继续完成密码初始化；否则明确标记为需要人工处置。更稳妥的方案是持久化非敏感阶段状态，并为“对象已创建、密码未设置”提供专门恢复路径，而不是重新执行 `add`。

### 2. 成功的移动 OU 操作不会更新本地域对象镜像，紧接着的后续操作会继续使用旧 DN

- 位置：`py/net/net/tasks/domain.py:72-77`，`py/net/net/tasks/executors/domain.py:137-144`、`168-188`
- 现象：入队时把当前 `distinguished_name` 固化到目标快照；Worker 成功后只写目标状态和结果快照，不更新 `Domain_Account` / `Domain_Computer` 的 `distinguished_name` 与 `ou`。因此移动 OU 成功后，在下一次同步前从页面继续执行加组、停用等操作，新任务仍会快照旧 DN，LDAP 将针对已不存在的旧路径执行。
- 影响：跨阶段真实用户流程“移动 OU → 对同一对象继续操作”会失败；列表中的 OU、启用状态等也会在同步前误导操作者。
- 修复建议：让 LDAP 动作结果返回变更后的稳定身份；在受租约保护的成功持久化事务中，根据目标类型和 `target_id` 更新本地 DN/OU（启用/停用同样更新 `is_active`）。若不维护写后镜像，则成功后必须强制同步并在同步完成前阻止对该对象继续写入。

### 3. 下载接口允许已停用分析配置，但生成的脚本必然被上传接口拒绝

- 位置：`py/net/index/views/scripts.py:48-54`，`py/net/net/views.py:36-41`
- 现象：脚本下载通过主键获取配置，不检查 `is_enabled`；脚本把该 profile UUID 固化到上传 URL。上传接口则只在 `is_enabled=True` 的配置中查找该 UUID，所以从停用配置下载的脚本每次上传都会返回 400“配置不存在或已停用”。
- 影响：下载成功并不代表脚本可用，破坏“选择配置 → 下载 → 上传 → Worker 分析”的真实流程。
- 修复建议：优先在下载端拒绝停用配置并给出“先启用配置”的明确提示，同时移除对应下载按钮。若产品确实要求下载历史/停用配置，则下载响应必须明确标记不可执行，不能把它作为可部署采集脚本提供。

## Minor

### 4. 域控确认摘要不会随目标 OU 输入更新

- 位置：`py/net/index/templates/domain/operation_modal.html:78-93`
- 现象：确认摘要只在动作或目标勾选变化时调用 `refresh()`；用户打开弹窗后输入“目标 OU DN”，摘要仍显示 `—`。提交事件中的刷新发生得太晚，用户无法在提交前核对影响范围。
- 影响：不满足设计要求的“提交前显示动作、目标数量和影响范围”，增加误操作概率。
- 修复建议：为目标 OU（以及组 DN）输入绑定 `input`/`change` 事件，并在最终提交前显示可见、最新的目标 OU/组摘要。
